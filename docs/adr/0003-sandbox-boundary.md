# ADR-0003 沙箱边界：任意代码只在沙箱里跑，沙箱不是操作生产机的通道

- 状态：已采纳
- 日期：2026-09-29
- 相关：`server_agent/sandbox/`、`server_agent/tools/sandbox_tool.py`、[ADR-0002](0002-no-arbitrary-shell.md)、第 11 章讲义、[sandbox 模块文档](../modules/sandbox.md)

## 背景

ADR-0002 规定不给 Agent 任意 shell：它能调的只有校验过的专用工具。到了第 11 章出现一个新需求：
固定工具覆盖不了的分析（例如「把 5xx 按分钟聚合」「把两段日志按请求 id 对齐」），
最自然的做法是让 Agent **自己写一段 Python**（CodeAct：用代码当动作）。

这等于把「模型生成的任意代码」引进来了，和 ADR-0002 看起来矛盾。可选做法：

| 方案 | 说明 | 问题 |
|---|---|---|
| A. 在 Agent 所在机器上直接 `exec` / 起子进程 | 最简单 | 模型代码能读 `.env`、SSH 私钥、SQLite 记忆库，能联网外发 |
| B. 在目标服务器上跑 | 数据就在那里 | 等于绕过 ADR-0002，变成了任意 shell |
| C. 在隔离沙箱里跑，数据由 Agent 显式送进去 | 本地 Docker 或腾讯云 AGS | 多一层基础设施；沙箱里看不到目标机 |
| D. 不支持 CodeAct | 最安全 | 分析类问题只能靠模型「心算」日志，结论不可信 |

## 决策

**采用 C**，并把边界写死成四条：

1. **任意代码只能在沙箱里执行**。唯一入口是 `run_python` 工具；项目里不存在「在宿主机或目标机上执行模型代码」的路径。
   新增任何执行代码的能力都必须走 `Sandbox` 协议（`server_agent/sandbox/base.py`）。
2. **沙箱不是操作生产机的通道**。沙箱里不放任何目标服务器凭证（SSH 私钥、inventory、API Token）；
   本地 Docker 后端 `--network none`，AGS 后端依赖其默认网络策略（不通 VPC，不作为跳板）。
   操作目标机只能走执行器（`server_agent/executors/`）+ 策略层 + 审批。
3. **数据单向、最小化进入**。沙箱里的代码拿不到任何主机数据，只能读 Agent 通过 `data_files` 显式放进去的内容
   （只读挂载到 `/data`，总量上限 40 万字符）；只把 stdout 带回来。
4. **后端显式选择，收费后端不隐式启用**。默认 `SA_SANDBOX_BACKEND=auto`：只有 `E2B_API_KEY` 与 `AGS_ENABLED`
   同时存在才用 AGS，AGS 配置不全就回退本地 Docker，不挡主流程；显式写 `SA_SANDBOX_BACKEND=ags` 时不回退，
   配置不全直接报「沙箱不可用」（你明确要云端，就不该悄悄在本地跑）。

`run_python` 定级 `low`（审计留痕、不要审批）：它不改变任何系统状态，隔离由沙箱负责；
如果后续给沙箱开网络或挂载可写目录，必须重新评审这个定级。

## 原因

- **沙箱和策略层管的是两种不同的自由**：策略层约束「能调哪些工具、传什么参数」（ADR-0002），
  沙箱约束「生成的代码能碰到什么」。代码的自由度没办法用参数白名单校验，只能靠隔离。
- **沙箱里能读到的，就等于模型能读到的**。只要里面有凭证，一次提示词注入就能把凭证打印进 stdout 回到模型上下文，
  所以凭证永远不进沙箱。
- **沙箱能直连生产机，就等于重新发明了任意 shell**。ADR-0002 的全部保证（白名单、审批、审计）都会被一条
  「沙箱里 `ssh prod rm -rf`」绕过去。

## 后果

- 正面：CodeAct 的灵活性只落在分析层；即使模型被注入，最坏结果也只是在一个没网、只读、限资源、用完销毁的容器里空转。
- 负面：
  - 沙箱看不到目标机，分析前必须先用只读工具把数据取回来，多一步，也多一份 token。
  - 本地 Docker 后端需要 daemon；没有 Docker 也没有 AGS Key 时，`run_python` 直接不可用（返回可读错误，不回退到宿主机执行）。
  - 容器共享宿主内核，隔离强度弱于 AGS 背后的 MicroVM；多租户或更敏感的场景应切 AGS。
- **暂不落地的部分**（SYLLABUS 第 11 章原计划，此处明确推迟）：
  - **沙箱预演**（审批前在同镜像沙箱里先执行一遍高危操作）：只对有一致镜像的环境（靶场、容器化服务）成立，
    对普通物理机/虚拟机不成立；目前审批卡片展示的仍是第 09 章的 dry-run 结果。
  - **`lab/ags/`**（用 AGS 自定义沙箱承载靶机）：没有 Key，无法在真实环境验证，先不交付未验证的配置。
  两者要做时，必须遵守上面四条：预演用的沙箱同样不能拿到生产凭证。
- 约束：代码评审时发现以下任一情况，视为违反本 ADR —— `exec`/`eval`/`subprocess` 执行模型输出；
  沙箱挂载可写的宿主目录；沙箱环境变量里出现凭证；沙箱镜像里内置 SSH 客户端配置。
